本页是纯静态页面，没有后端。打开时它会向上面配置的服务地址发起只读 GET 请求（附带 _ts 时间戳参数以绕过缓存），不发送任何数据，也不携带 Cookie 或凭据（credentials: omit）。探测结果只存在当前页面的内存里，刷新即消失。

判定规则

状态 颜色 条件
运行正常 绿 请求成功、响应体匹配 expectText、总耗时 < slowMs
延迟偏高 琥珀 请求成功，但总耗时 ≥ slowMs（默认 800 ms）
响应异常 橙 请求成功，但响应体不包含 expectText（服务活着但接口内容不对）
服务不可用 红 网络失败、超时，或 HTTP 状态码 ≥ 400
检测中 蓝 正在探测（第一次探测前也显示蓝色）
未检测 灰 还没有拿到结果

探测优先走 CORS 请求，能读到状态码和响应体；如果目标没有开放 CORS，会自动退化成 no-cors 不透明请求 —— 这时只能确认「服务可达」，状态码与内容无法校验，界面会如实标注。

延迟是怎么测的

页面不自己数秒表，延迟取自浏览器的 Resource Timing API：请求发出后用 performance.getEntriesByType("resource") 找到这次请求的条目，读它的 duration，也就是浏览器记录的 responseEnd - startTime，包含排队、DNS、连接、TLS、TTFB 和内容下载的全部真实网络耗时。

几个细节：

  • 请求默认带上 _ts 时间戳绕开缓存，否则缓存命中时 Resource Timing 耗时会是 0，测不出真实延迟。
  • 跨域资源只有在服务端返回 Timing-Allow-Origin 时，浏览器才允许读取 DNS / TCP / TLS / TTFB 这些分阶段字段；否则它们会被清零，页面只显示总耗时并给出提示。
  • 极端情况下（请求被拦截、环境不支持）拿不到 Resource Timing 条目，则退回 performance.now() 差值计时，界面会说明来源。
